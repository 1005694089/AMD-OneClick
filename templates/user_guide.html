Developer User Guide

Build and run GPU notebooks on Radeon Cloud

This guide explains the main developer workflows: creating templates, launching and deleting GPU instances, managing credits, and using persistent storage safely.

Quick Start

  1. Sign in from the Profile page.
  2. Open the Gallery and choose a prepared notebook template, or switch to Notebook to launch a blank OpenCode-ready workspace.
  3. Choose your GPU count and, when available, CPU/memory profile. Use larger profiles for memory-heavy workloads.
  4. Wait until the instance is ready, then click Open Notebook.
  5. When finished, delete the instance from Profile to stop consuming credits.

Notebook Templates

Templates package a container image plus optional GitHub repository metadata so other developers can preview and launch a reproducible notebook environment.

Create a template

  1. From the Gallery page, click Create Template.
  2. Enter a title, description, category, tags, and container image.
  3. For a notebook template, provide the GitHub repo URL, branch, and notebook path. Leave repo and path empty for an image-only workspace.
  4. Save the template. Editor/admin approval may be required before a template is visible to everyone.

Preview and launch

Use Preview to inspect notebook content before launching. Preview content is cached by the platform, so changes in GitHub may take time to appear unless an administrator refreshes the preview cache.

Instances

One active instance per account.
Each account can keep only one active GPU instance. Delete the current instance before launching another.

Launch an instance

  1. Launch from a Gallery template or from ?tab=notebook.
  2. Select GPU count. Credit usage is charged per GPU-hour.
  3. For blank notebooks, select CPU/memory profile. Auto currently scales memory with GPU count.
  4. Open the notebook when status becomes ready.

Delete an instance

Go to Profile, find Active Instance, then click Destroy Instance. This stops billing and releases GPU resources. Your persistent files remain according to the storage rules below.

Credits

Credits control GPU usage. Running instances are charged by GPU count and runtime. For example, a 4-GPU instance consumes credits faster than a 1-GPU instance.

Credit redemption may be temporarily unavailable.
If redemption is disabled during system maintenance, contact the administrator for credits.
  1. Check available credits on the Profile page.
  2. If redemption is enabled, paste your coupon in Redeem Credits.
  3. If your credits run out, the platform may automatically delete the running instance. Save your work regularly.

Persistent Storage

Instances expose two storage locations. Use them intentionally.

/workspace Local persistent workspace bound to the current node. It survives container restarts such as OOMKilled, but may not follow the instance if it is recreated on another node.
/network-workspace Network workspace when enabled. It is backed by a per-instance 20Gi network disk and can be mounted from different nodes.
/root/.cache/huggingface Shared model cache used by selected base images. Do not use it for private project files.
Recommended: put notebooks, scripts, checkpoints, and results that must survive restarts under /network-workspace when it is available. Use /workspace for fast local scratch data tied to the current instance.

Usage Rules

Radeon Cloud is intended for development, evaluation, education, and research workloads on AMD GPUs.

  • Do not run cryptocurrency mining or unrelated background workloads.
  • Do not share credentials, coupons, or access tokens.
  • Do not attempt to bypass credit, storage, or instance limits.
  • Delete idle instances promptly to free GPU capacity for other developers.

Troubleshooting

Instance is slow to start

Large images may take time to pull. If launch takes unusually long, refresh Profile and check whether an active instance exists.

Notebook files disappeared after restart

Files under /network-workspace should survive instance recreation when network disk is enabled. Files stored outside /workspace or /network-workspace may be part of the container filesystem and can be lost.

Out of memory

Use a larger CPU/memory profile when launching from the Notebook tab. For 2-GPU and 4-GPU workloads, Auto recommends larger memory profiles.

Need help

Contact the platform administrator with your account email, instance id, template name, and a short description of the issue.
